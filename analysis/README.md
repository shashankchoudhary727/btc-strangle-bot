# Analysis — BTC Short Strangle Edge Validator

This folder contains the full statistical validation of the BTC Short Strangle strategy. The analysis runs on `trades.csv` generated by the live bot and covers 1,934 leg-trades (967 strangles) collected between May 23 and Jul 28, 2026.

---

## How to Run

```bash
cd analysis
pip install pandas numpy matplotlib seaborn scipy nbformat jupyter
jupyter notebook edge_validator.ipynb
```

Place `trades.csv` (from the repo root) in this folder before running, or update the path in Cell 1.

## Notebook Structure — `edge_validator.ipynb`

The notebook has 11 sections, designed to be read top to bottom as a research report.

**Section 1 — Data Loading & Overview**  
Loads `trades.csv`, parses timestamps, derives `leg` (call/put), `win` (bool), and `equity` columns. Prints shape, date range, and column types.

**Section 2 — Performance Summary**  
Computes and prints all key metrics in a formatted table: win rate, total PnL, avg win/loss, expected value per trade, Sharpe, Sortino, max drawdown.

**Section 3 — Equity Curve**  
Two-panel chart: cumulative equity over all trades with drawdown shading below, and a standalone drawdown subplot. Shows the growth trajectory and the worst peak-to-trough periods.

**Section 4 — Win Rate Analysis**  
Three charts: win/loss donut pie, PnL distribution histogram (wins vs losses overlaid), and 100-trade rolling win rate. The rolling chart shows whether the edge is stable or drifting.

**Section 5 — Hourly Performance Breakdown**  
Two bar charts showing win rate and avg PnL for each of the 24 UTC entry hours. This is the core research output — identifying which hours have structural edge and which destroy capital.

**Section 6 — Exit Reason Analysis**  
Pie chart of exit type distribution (TARGET / TRAILING SL / HARD SL / MANUAL) and avg PnL per exit type. Key finding: only 0.7% of trades hit the profit target — the trailing SL is doing all the work.

**Section 7 — Call vs Put Performance**  
Win rate, avg PnL, and total PnL split between call and put legs independently. Reveals whether one leg type is consistently dragging performance.

**Section 8 — Statistical Significance (t-test)**  
One-sample t-test of win rate against the 50% null hypothesis. Includes t-statistic, p-value, 95% confidence interval, and a visualised t-distribution with rejection region shaded. Result: p < 0.001 — the edge is statistically real.

**Section 9 — Monte Carlo Simulation (1,000 runs)**  
Resamples the observed trade PnLs 1,000 times to estimate the distribution of possible equity paths and max drawdowns. Three charts: sample paths overlaid on actual, final equity distribution, and MDD distribution. Answers the key risk question: even if the edge is real, how bad can it get?

**Section 10 — Risk Metrics Scorecard**  
Visual summary table with ✅ / ⚠️ / ❌ signals for every key metric. Designed to give an at-a-glance view of what works and what doesn't.

**Section 11 — Best Trading Hour: Isolated Strategy Comparison**  
The research conclusion section. Compares four strategy variants:

| Variant | What it tests |
|---|---|
| All 24 Hours | Baseline — running the bot as-is |
| Hours 6–8 UTC | The top-performing cluster |
| Hour 8 UTC only | The single best hour |
| Worst Hours (11, 12, 14) | The hours to avoid |

Three charts: equity curves for each variant side by side, bar comparison of win rate / Sharpe / PnL / MDD, and a full hourly heatmap with green/red trading zones marked. Ends with the research conclusion and next-phase deployment plan.

## Key Findings

**The edge is statistically real** — win rate 60.8%, t-stat 9.73, p < 0.001 on 1,934 trades.

**But most hours are noise or negative** — hours 11, 12, and 14 alone destroyed -$1,797 in PnL. Running all 24 hours dilutes the genuine edge with bad entries.

**Hour 8 UTC is the structural winner:**

| | All 24h | Hour 8 only |
|---|---|---|
| Trades | 1,934 | 60 |
| Win Rate | 60.8% | **71.7%** |
| Sharpe | 1.29 | **8.28** |
| Max Drawdown | -$2,718 | **-$215** |

The 24-hour research mode has served its purpose. The next deployment phase is a single-entry-per-day bot targeting Hour 8 UTC exclusively.

## Data Format — `trades.csv`

The bot logs every leg exit to `trades.csv` with no header row.

| Column | Type | Description |
|---|---|---|
| timestamp | datetime | UTC time of exit event |
| trade_mode | str | PAPER or LIVE |
| symbol | str | Option symbol (e.g. C-BTC-75800-240526) |
| entry_hour | int | UTC hour the strangle was entered (0–23) |
| side | str | Always SELL (short strangle) |
| entry_premium | float | Premium collected at entry ($) |
| exit_premium | float | Premium at exit ($) |
| quantity | int | Lot size (1) |
| stop_loss | float | Hard SL level ($) |
| target | float | Profit target level ($) |
| pnl | float | Realised PnL for this leg ($) |
| capital | float | Running capital after this trade ($) |
| exit_reason | str | TARGET / HARD SL / TRAILING SL / MANUAL EXIT |

Symbol prefix `C` = call leg, `P` = put leg.
